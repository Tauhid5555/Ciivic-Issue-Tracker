01What we built

A civic-issue tracking system with two portals — one for residents, one for staff. Every screen is clickable; no backend required to demo.

Two portals, one shared model

Portal 01

Citizen Portal

Resident flow: submit a report, receive a Tracking ID, follow status, dispute a fix, view personal history via magic-link.

Submitted Acknowledged In Progress Resolved Disputed

Portal 02

Admin Portal

Staff workspace: queue with bulk actions, report-detail drawer with status workflow, advanced filters, account/sign-out.

Duplicate · 32 demo reports · 8 categories

The prototype

  • 23 screens — 13 Citizen Portal + 8 Admin Portal + flow map + root overview.
  • 15 page specs in C-UX-Scenarios/, each realized 1:1 as a screen.
  • 32 demo reports across every category, every status, mixed priority, last 30 days.
  • Live interactivity — filter, sort, paginate, single-row actions, bulk actions, notes, toasts, lightbox.
  • Zero backend — pure HTML + CSS + JS. Open index.html in any browser.
  • Responsive — Citizen Portal stays narrow with enrichment at lg+; Admin Portal gains a sidebar at xl+.

06Decisions along the way

Major decisions captured in the design log.

Design concept

Friendly Civic Accountability — warm, plain-spoken, status-as-hero.

Authority auth

Invited admins with email/password for v1; SSO deferred to v2.

Dashboard tone

Calm and efficient, dense, optimized for 5-second tasks.

Citizen narrow column

Stays at 640px content width; type and gaps enrich at lg+.

Dashboard responsive

Filters: drawer below lg, persistent 240px sidebar at xl+. Detail: bottom sheet below md.

Anti-enumeration

Same timing/response for 400/404/500 on public lookups. Magic-link: same response regardless of email existence.

Renames

Authority Dashboard → Admin Portal. Maple Heights → [Your City]; product reads as ReportIt.

Portal isolation

Citizen and Admin do not link to each other. They meet only at the root index.html.
